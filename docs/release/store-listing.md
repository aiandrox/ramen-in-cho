App Store Connect と Play Console に入力する文の下書き（入力は aiandrox が行う）。プライバシーの回答は [README.md](README.md) の「ストアのプライバシーの回答」。

決まり:

- 無料・広告なし・課金なし・ログインなし
- 「ラーメン二郎」など実在の店名・チェーン名は、説明文・キーワード・画像に出さない（手で持つ店の一覧は事実としてアプリに持つだけ）

- 架空の店名・地名だけを使う。厚木・本厚木・海老名とその周辺は使わない

### 説明（App Store・Google Play の詳しい説明、4000文字以内）

```
麺印帳（めんいんちょう）は、食べたラーメンを一杯ずつ記録し、印を集めていく「麺道の修行帳」です。

御朱印帳に印をいただくように、一杯食べるごとに帳面へ印が押されます。
長い行列に並んだ一杯、限定の一杯、遠くまで足をのばした一杯。
杯数ではなく「攻略」の手ごたえが修行点になり、段位が上がっていきます。

■ 店内で、片手で記録
・着丼したら、写真を撮るかギャラリーから選ぶだけ
・近くのラーメン店が候補に出るので、タップで店が決まります
・「着丼！」で保存。評価や系統は、食べ終わってからでも付けられます
・電波が届かない店でも、店名を入れればその場で記録できます
・ギャラリーの写真は撮影日時と撮影場所を読み取るので、昔の一杯もまとめて記録できます

■ 修行点と段位
・並び始めから着丼までの時間、限定、初訪問、撤退からの再挑戦、朝ラー・深夜の一杯
・拠点から離れた遠征、初めての都道府県・市区町村
・同じ店に通う、毎週続ける、名店の印をつけた店で食べる
攻略するほど修行点が増え、入門から五級、初段、そして免許皆伝へと段位が上がります。

■ 印を集める
・一杯ごとの印は、修行点で良・秀・妙・極の格が、店のある地方で外枠が変わります
・回数を重ねて段が上がる「型」と、一度きりの「秘伝」を会得していきます
・印帳は一杯一頁。店のページでは、その店で集めた印を並べて見られます

■ 並ぶ・撤退する
・「いま並んでいる」で並び始めると、着丼までの時間を自動で測ります。並び始められるのは店の近くにいるときだけです
・売り切れや臨時休業で食べられなかった日は「撤退」として残せます。次に食べられたら「再挑戦成功」

■ 願掛け帳
行きたい店に願を掛けておけば、記録するときに候補の先頭に出ます。
その店で食べると「願成就」。誰に聞いたか、どこで見たかも書き留められます。

■ 振り返る
・一杯ごとに、記録から短い道中記が綴られます
・地図で行った店と、食べた順の旅路をたどれます
・一年の振り返り、統計、一年前の今日の一杯
・一杯を写真と印の一枚の絵にして、家族や友だちに送れます

■ 記録はスマホの中に
記録・写真・メモはスマホの中だけに保存し、運営者のサーバーには送りません。
ログインやアカウントは要りません。
機種変更のときは、バックアップのファイルで記録と写真を引き継げます。
位置情報は、アプリを使っている間だけ、近くの店を探すために使います。

■ 料金
無料です。広告の表示やアプリ内の課金はありません。

店の情報は OpenStreetMap などのデータをもとにしています。新しい店や小さな店が載っていないことがあります。
```

```
ログインやアカウントは無く、すべての機能をそのまま使えます。アプリは無料で、広告もアプリ内課金もありません。

【記録の流れ】
1. 画面下の中央にある「麺」の判子をタップし、「着丼した」を選びます
2. 「カメラで撮る」か「ギャラリーから選ぶ」で写真を選びます。写真は無くてもかまいません
3. 近くのラーメン店が候補に出たら、タップして店を選びます。候補が無いときは店名を入力します
4. 「着丼！」で保存すると、印が押され、修行点が表示されます

【位置情報】
位置情報は、アプリを使っている間だけ使います。近くのラーメン店を候補に出す、店の近くで「並んでいる」を始める、地図に現在地を出す、の3つに使います。アプリを閉じている間の位置情報は使いません。Info.plist の NSLocationAlwaysAndWhenInUseUsageDescription は、使っている部品の geolocator が「常に許可」の API を参照しているために書いているもので、「常に許可」は求めません。位置情報を許可しなくても、店名を入力して記録できます。

【共有の拡張機能 Share Extension】
写真アプリや地図アプリの共有シートで「麺印帳」を選ぶと、その写真から記録を、共有された店の名前・住所・リンクから記録や願掛けを始められます。願掛けは行きたい店のメモです。拡張機能は受け取った写真・文を App Group の領域に一時的に置いてアプリを開くだけで、通信はしません。

【通信】
店の検索は運営者のサーバー ramen-in-cho.aiandrox.com を通して行い、サーバーの API は Firebase App Check の App Attest でアプリからの問い合わせだけを受け付けます。審査の端末で App Check が通らないときや通信できないときも、アプリは端末から直接の検索に切り替えるか、店名の手入力で記録できます。記録・写真はサーバーに送らず、端末の中だけに保存します。

【試すときのヒント】
近くにラーメン店が無い場所では候補が出ないことがあります。その場合は店名に「麺屋 テスト」のような任意の名前を入れて「着丼！」を押してください。
```

## スクリーンショット

画像は `docs/release/screenshots/` にある（アプリには入れない）。使い方の絵と同じく、架空のデータで実際の画面を描き、上に見出しを重ねている。画面を変えたら、macOS で次のコマンドを実行して作り直す（JPEG にするのに macOS の `sips` を使う）。

```bash
flutter test --dart-define=UPDATE_STORE_SHOTS=true test/tool/store_shots_test.dart
```

ふだんの `flutter test` は画像を書き換えず、どの場面も描けることと、画像がそろって下の大きさであることだけを確かめる。データ・場面・見出し・大きさは `test/tool/store_shots_test.dart` にまとめてある。

### 決まり（2026-10-08 に公式の案内で確かめた）

- App Store（[スクリーンショットの仕様](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications)）: JPEG か PNG、透過なし、1つの枠に1〜10枚。iPhone は 6.9インチ（1320×2868 など）があれば小さい iPhone にはそれを縮めて使う。6.5インチ（1284×2778 など）は 6.9インチが無いときに要る（念のため両方作った）。**iPad で動くアプリは iPad 13インチ（2064×2752 など）が要る**
- Google Play（[プレビュー アセット](https://support.google.com/googleplay/android-developer/answer/9866151)）: JPEG か透過なしの 24bit PNG。辺は 320〜3840px、長い辺は短い辺の2倍まで。公開には2枚以上、おすすめ枠に載るには 1080px 以上の縦長（9:16）を4枚以上。フィーチャー グラフィックは 1024×500
- 透過が入らないよう、どれも JPEG にした
